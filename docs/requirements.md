# Offer 捕手 — 需求分析文档

> 内部产品需求，供开发参考。用户使用说明见 [用户指南](./用户指南.md)。

## 1. 项目背景

学生在求职过程中面临：**岗位搜寻耗时**、**简历匹配度不确定**、**不知如何优化简历**三大痛点。本项目提供 AI 驱动的岗位推荐、匹配分析与简历优化能力。

## 2. 目标用户

- 在校大学生、应届生
- 寻求实习 / 校招机会的学生

## 3. 功能需求

### 3.1 用户与认证（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| U-01 | 用户注册 | 邮箱+昵称注册，邮件链接设密后登录 |
| U-02 | 用户登录 | JWT 令牌，未登录无法访问主功能 |
| U-03 | 演示账号 | 初始化 `demo@student.edu` / `demo1234` |
| U-04 | 忘记密码 | 邮件重发设密链接 |

### 3.2 求职画像（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| P-01 | 填写意向城市、岗位、行业 | 可保存并在匹配中使用 |
| P-02 | 选择求职类型 | 实习 / 校招 |

### 3.3 简历管理（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| R-01 | 上传 PDF/DOCX/TXT | 解析为结构化 JSON |
| R-02 | 版本管理 | 新上传自动设为当前有效简历 |
| R-03 | 删除简历 | 侧栏删除；删当前则自动激活最新一条 |

### 3.4 岗位匹配（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| M-01 | 岗位库 | 预置种子岗位；支持录入、粘贴、截图、AI 导入 |
| M-02 | 智能推荐 | 返回 Top-K 及匹配分、说明 |
| M-03 | 单岗报告 | 匹配项、缺口、风险、投递建议 |
| M-04 | 账号隔离 | 用户录入岗默认仅本人可见 |
| M-05 | 岗位共享 | PATCH share；他人可见并标注来源 |
| M-06 | 列表简历分析 | 岗位库列表/详情「结合简历分析」 |

### 3.5 简历优化（P1）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| O-01 | 针对岗位优化建议 | 分 P0/P1 优先级，禁止编造经历 |
| O-02 | 改写片段 | 返回 suggested 文本供参考 |

### 3.6 智能对话（P0）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| C-01 | 对话主界面 | 居中输入、Markdown 回复、侧栏会话与简历 |
| C-02 | 导航 | 顶栏「Offer 捕手」返回三主入口 |
| C-03 | 退出确认 | 确认框 + 退出动画，防误触 |
| C-04 | 用户 API Key | 侧栏配置 DeepSeek Key（加密存储） |

## 4. 非功能需求

- **部署**：Docker Compose 一键启动
- **性能**：推荐接口 Top10 在 60s 内返回（含 LLM 精排）
- **安全**：密码 bcrypt；JWT；API Key 仅环境变量
- **可维护**：OpenAPI 文档 `/docs`

## 5. 约束与假设

- 岗位数据 MVP 使用种子数据，后续可接爬虫/API
- 大模型使用 DeepSeek Chat API（OpenAI 兼容）
- 不对简历经历真实性做法律级核验，需界面提示用户诚信

## 6. 版本规划

| 版本 | 范围 |
|------|------|
| v1.0 | 基础 MVP：认证、画像、简历、匹配、优化、对话、Docker |
| **v1.1（当前）** | 邮件设密注册、用户 API Key、岗位隔离与共享、列表简历分析、简历删除、导航/退出体验、部署与用户文档 |
| v1.2 | 向量检索 pgvector、投递状态追踪 |
| v2.0 | 岗位爬虫、管理后台 |
